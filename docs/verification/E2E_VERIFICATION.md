# AbstractX E2E Verification Architecture

To guarantee that the isolated IP cores actually function safely when compiled into a bitstream, developers MUST use the **AbstractX E2E Verification IP (VIP)** to construct integration tests. 

This philosophy is heavily inspired by **Vivado's AXI Verification IP (AXI VIP)**, where standard hardware behavior is validated by executing fully instrumented host-level bus agents instead of writing manual state machine toggles.

## What is the `AbstractX_VIP`?
The `AbstractX_VIP` (located in `sim/cocotb/asp_e2e_vip.py`) is a reusable Python driver that perfectly emulates the future Linux kernel/userspace drivers interacting with physical FPGA pins.

It eliminates the need to manually bit-bang `MOSI`, `MISO`, `CS`, and `SCLK` during your tests, allowing you to rapidly tunnel **any** packet into the top-level generic simulation architecture.

## Writing an E2E Modular Test

By plugging this VIP into your top-level simulated module (typically `asp_top.sv` or your custom project branch), you can easily add arbitrary tunneling and verify custom hardware downstream.

### Example E2E Python Architecture:

```python
import cocotb
from cocotb.clock import Clock
import struct
from asp_e2e_vip import AbstractX_VIP

@cocotb.test()
async def test_your_custom_hardware_e2e(dut):
    # 1. Provide the physical simulator dut to the VIP
    vip = AbstractX_VIP(dut, clk_domain_freq_mhz=100, spi_freq_mhz=5)
    
    # 2. Hardware constraints auto-reset
    await vip.reset_hardware()
    
    # 3. Tunneling Data - Pack your custom application payload!
    # (Example here shows constructing a 8-byte arbitrary framing payload).
    my_custom_payload = struct.pack(">BBBBBBBB", 0x10, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x04)
    
    # 4. Stream directly into the SPI FPGA pins 
    await vip.write_stream(my_custom_payload)
    
    # 5. Check FPGA processing logic across clock domains
    # Let your arbitrary design process the payload...
    
    # 6. E2E Egress Handshake (Verification)
    rx_len = 0
    for _ in range(50):
        _, _, rx_len = await vip.read_status()
        if rx_len > 0:
            break
            
    assert rx_len > 0, "No response generated by custom hardware module."
    
    # 7. Extract the downstream response payload
    response_bytes = await vip.read_stream(rx_len)
    
    assert response_bytes[0] == 0x00 # Validate custom payload formatting
```

## Developer Modular Rule
If you author a unique **AXI-Stream Hardware Module** inside `rtl/`, you must first test it in isolation using the `ASP_AXIS_Monitor` hostile protocol checker. But once verified, it must be integrated into `asp_top.sv` (or equivalent) and tested through this highly permissive `AbstractX_VIP` to ensure that standard host networking stacks can actually push and receive data through it natively.
